Ibarra is the Jakarta Pages 4.0 (formerly JavaServer Pages) implementation of the Vidocq ecosystem, in pure Java 25: zero third-party dependency, strict Java Modules, and pages translated and compiled during the application build instead of inside the running server.

Ibarra’s I3/I6 generation is in progress. Runtime/parser, Maven packaging, Foy HTTP binding, TLD listeners, initial classic/simple tags, compiled EL, page imports/functions, atomic shared beans and typed deferred tag attributes are implemented. Startup interpretation requires an explicit preview option. Full tag semantics and certification remain pending. This documentation describes the 0.4.0-SNAPSHOT development line.

Origin of the name

Joaquín Ibarra y Marín (1725–1785), royal printer in Madrid, celebrated for the 1780 edition of Don Quixote published for the Real Academia Española — one of the finest books of Spanish printing. See the Wikipedia article.

The name is a nod to Cervantes, the MicroProfile JWT brick of the ecosystem. And it describes the engine: a printer composes the pages once, carefully, then prints them on demand. Ibarra composes each page — translation, compilation, tag wiring — during the build, so that a request only has to print it.
