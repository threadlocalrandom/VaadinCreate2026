Peano is the Jakarta Expression Language 6.0 implementation of the Vidocq ecosystem, in pure Java 25: zero third-party dependency (only the jakarta.el spec jar), strict Java Modules, and — like every Vidocq brick — property accessors and expressions generated at build time where others reflect at run time.

Peano is in development (P6): grammar, operators, coercions and the ExpressionFactory provider are implemented. Resolver-backed value expressions now navigate models, capture variables and expose get/set/metadata with imports and static fields. Functions, method expressions, method references and assignments are implemented. Lambda execution, list/set/map construction and lazy chapter 2 collection pipelines and compiled adapters for all java.util.function interfaces, Runnable, Callable and Comparator are implemented. Selected application interfaces use generated adapters; known API limitations are recorded in BUG.md. Evaluation listeners and expression serialization are implemented. The peano-api accessor-table service and direct resolver dispatch are implemented. APT property generation supports @ELAccessible and explicit selected types. Direct public method calls and generated signatures/runtime annotations are implemented. All 361 official EL 6.0.1 TCK tests pass on Temurin 25, including signatures. This is a test result, not a certification announcement. This documentation describes the intended 0.4.0-SNAPSHOT development line; every page states what exists today.

Origin of the name

Giuseppe Peano (1858–1932), the Turin logician who gave mathematics a rigorous formal notation — the ∈ symbol, the axioms of arithmetic that bear his name, the Formulario mathematico. See the Wikipedia article.

Peano wanted expressions written in a notation without ambiguity, so that evaluating them became a mechanical act. That is the whole job of an Expression Language engine: parse ${order.total * 1.2} into one unambiguous tree, then evaluate it the same way every time.
